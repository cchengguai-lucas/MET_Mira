## 06 核心问题与目标用户（约 249 字，建议 150—300 字）

```text
面向软硬件协同的设备研发场景，本项目重点解决跨专业需求流转割裂、联调状态不透明与交付排期失控问题。目标用户覆盖需求提出人、电气/机械/软件研发工程师、测试工程师、项目经理（PM）及研发管理者。当前企业普遍依赖 Excel 需求表、即时通讯群和孤立的软件 Jira 拼凑协作，主要不足在于：需求录入与拆分依赖人工，易重复遗漏；方案变更缺乏多方会签与实质变更识别；软硬件联调进度靠口头同步，测试入口缺少强门禁；任务阻塞依赖与延期风险只能靠经验估算，管理者难以基于真实数据提前干预，无法形成可追溯的端到端交付闭环。
```

## 07 实现思路与核心功能（约 366 字，建议 200—400 字）

```text
以 Mira 协同交付平台为底座，围绕“需求建单→方案会签→研发联调→测试验收→排期风控→周报复盘”构建人机协同交付闭环。核心功能由多能力 Agent 分工交接：1）需求起草与分诊 Agent 将自然语言/Excel 拆解为 Epic 与子任务，自动查重并推荐负责人；2）流转门禁 Agent 在进入研发前强制电气/工艺/软件三方会签并由大模型识别方案实质变更，研发中定时同步软件 Jira 快照，就绪后自动交接测试；3）排期风控与工作流 Agent 基于不可变基线与阻塞图计算级联延期，生成待 PM 确认的改期建议，并支持自然语言诊断修复工作流，所有写操作经确认卡片执行并审计，通知经 Outbox 推送企微/邮件。

Qoder 将承担参赛迭代的端到端工程交付：完成多 Agent 交接协议编排、全栈增量开发与数据库迁移、自动化单测与 Playwright E2E 回归验证及沙箱演示环境构建。
```

3. 实景复现核验：执行一键重置沙箱后，在无后台手工改库的情况下完整跑通上述 4 步闭环，以拦截日志、审计记录与监控指标定量证明方案有效。
