# Error log — 2026-11-03

## Workflow repair stops on a missing status

- Symptom: In project CVDME001, 「修复全部错误」 makes a draft that still has errors. The draft cannot be applied to the canvas.
- Source: User report. Production project CVDME001, mechanical profile, workflow editor.
- Context: `backend/services/workflow_audit.py` `suggest_repairs`. The bug, requirement, story, task, epic, and subtask graphs still name 试装, 终检, 已完成, or 已驳回. Those statuses are not on the project. The four remaining statuses are all category doing. The project has no issues.
- Cause: The required repair only deletes lines to missing names. After that deletion there is no done status, so the repair cannot add a path to completion. The apply action rejects a draft that still has an error.
- Fix: A line that names a removed template status restores that status with its template category. A flow with no done status gains 「已完成」 and a path to it. 「修复全部错误」 applies those required repairs together. An instruction draft that is still invalid after one retry uses the same repairs.
