## 1. 技术栈与运行环境清单

| 层级 | 技术组件 | 版本 / 说明 |

## 2. 核心业务能力与源码模块导航（给 Qoder 的地图）

### 2.1 AI Agent 与智能协作
- `backend/services/agent.py`：确定性意图路由、服务端会话与滚动摘要、受权数据读取、写操作待确认卡片（Human-in-the-loop）、持久化记忆（仅用户显式确认后保存）
- `backend/services/agent_tools.py`：面向 Agent 的最小权限工具集定义与权限校验
- `backend/routers/agent.py`：对话、确认执行、工作流草稿优化（`/api/agent/workflow-draft`）等接口
- `backend/services/llm.py`：OpenAI 兼容接口封装（`chat` / `stream_chat` / tool calling 探测）
- `backend/services/workflow_assist.py` & `backend/services/workflow_audit.py`：工作流画布结构诊断、指令改造与自动修复
- `backend/services/jql_assist.py`：自然语言转 JQL 查询
- `backend/services/polish.py`：描述与交付说明 AI 润色（防幻觉约束）

### 2.2 软硬件交付门禁与跨系统联动
- `backend/services/workflow.py` & `backend/services/approvals.py`：可配置状态流转、必填字段门禁、多角色会签审批
- `backend/services/scheme.py`：进入“研发中”前的电气/工艺/软件三方方案确认门禁，以及基于 LLM 的方案实质变更比对与自动重置签核
- `backend/services/software.py` & `backend/services/software_jira.py`：软件就绪状态门禁、只读软件 Jira Relay 快照拉取（`GET /api/jira/relay?key=`）、“待上机验证”自动触发测试交接与延期邮件预警
- `backend/services/templates.py` & `backend/services/ai_template.py`：电气/机械/生产/AI 多部门可配置项目模板与 `issues.extra` schema 校验

### 2.3 不可变排期基线与级联风控引擎
- `backend/models/schedule.py`：不可变版本化基线 `ProjectScheduleBaseline`、风险事件生命周期 `ScheduleRiskEvent`
- `backend/services/schedule_cascade.py`：同项目 `blocks` 阻塞依赖图构建、强连通环路隔离、工作日级联传播、`analysis_token` 与乐观锁校验、逐项 applied/skipped/stale 报告
- `backend/services/pm_risk_alerts.py` & `backend/services/planning.py`：项目组合风险排序、交期影响计算、交付模式（`delivery`）与持续运维模式（`ongoing`）隔离

### 2.4 基础设施、数据导入与运维
- `backend/services/excel_io.py`：两行合并表头 Excel 智能解析、预览映射与整批撤销
- `backend/services/outbox.py` / `backend/services/sla.py` / `backend/services/reminders.py`：SLA 扫描、升级提醒与 Outbox 投递
- `backend/services/search.py`：JQL 解析器（含 `cf_<key>` 自定义字段）、`pg_trgm` 相似度查重与 Facet 缓存
- `backend/ops.py`：统一初始化入口（Alembic 迁移 + 模板/本地管理员播种 + 附件核对）
- `MET_Jira-ops/ops_console/`：完全独立的只读运维与 AI 效能观测控制台

## 3. 产品核心不变量（开发与改造时绝对不能破坏）

1. **交付项目 vs 持续项目**：`work_mode=delivery` 有目标日期、不可变基线与级联延期风控；`work_mode=ongoing` 保留完整 Issue 流程但无交付承诺与基线告警。
2. **不可变基线**：已发布的排期基线只读、按版本递增，不可原地篡改。
3. **排期紧急度与业务优先级分离**：两者独立计算，不互相覆盖。
4. **AI 写操作人机协同**：排期修改与写操作必须生成建议/待确认卡片，由具备权限的用户/PM 确认后落地，严禁静默改库。
5. **受权数据读取**：Agent 对实时业务数据的回答必须来自受权数据工具，不得凭空编造。
6. **测试与方案门禁不可被 AI 绕过**：三方方案确认与软件就绪确认不允许聊天助手代签。

## 4. 参赛现场重点改造技术点清单

1. **公网 LLM API Key 支持（赛前/现场最先做，约 10 分钟）**
   - 现状：`backend/services/llm.py` 原对接无鉴权内网网关，未发送 `Authorization: Bearer` 头。
   - 改造：在 `backend/config.py` 新增 `METJIRA_LLM_API_KEY`，在 `llm.py` 的 `httpx.post` / `httpx.stream` 加入可选 `Authorization` header；这样即可无缝切换 DeepSeek / 通义千问 / OpenAI / 赛事提供模型或本地 Ollama。
2. **多阶段交付交接编排层（核心任务 1）**
   - 在 `backend/services/` 新增交接编排服务（如 `delivery_handoff.py`），把“需求分诊 → 方案会签状态检查 → 软件 Jira 就绪联调 → 排期级联影响评估”串联成可追踪的交接流水线，并在前端展示“当前阶段 / 阻塞原因 / 建议动作 / 确认执行 / 审计轨迹”。
3. **Mock 软件 Jira Relay + 一键脱敏沙箱脚本（核心任务 2）**
   - 编写独立轻量 FastAPI Mock 服务（如 `scripts/demo/mock_software_jira.py`），提供 `GET /api/jira/relay?key=...` 和一键推进状态接口（如 `POST /mock/advance/{key}` 将状态改为 `待上机验证` 或调整 due date）。
   - 编写 `scripts/demo/seed_competition_sandbox.py`，一键清空并播种完整演示项目（多专业角色账号、阻塞依赖链、已发布基线、方案确认待签单、关联软件单号的联调单、即将触发级联延期的上游任务）。
4. **Playwright E2E 全链路验收 + 交付效能指标（核心任务 3）**
   - 在 `web/e2e/` 新增 `competition-delivery-loop.spec.ts`，自动化验证 4 步演示闭环。
   - 补充 Agent 交接耗时、确认采纳率、门禁拦截次数统计接口与前端看板展示。
